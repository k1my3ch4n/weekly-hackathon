# Phase 8: 통합 테스트 시나리오

## 8-1. E2E 흐름 테스트

### TC-01. 기본 음성 대화 흐름

**목적**: 음성 입력 → STT → LLM → TTS → 음성 출력 전체 파이프라인 정상 동작 확인

**전제 조건**:

- 봇이 Discord 서버에 연결된 상태
- 유저가 음성 채널에 입장한 상태

**시나리오**:

1. `/join` 명령어로 봇을 음성 채널에 참여시킨다
2. 유저가 영어로 발화한다 (예: "Hello, how are you today?")
3. 무음 감지 후 파이프라인이 시작된다

**기대 결과**:

- [x] 채팅창에 `🎙️ **유저명**: Hello, how are you today?` 출력
- [x] 채팅창에 한국어 번역 `> 번역: 안녕하세요, 오늘 어떠세요?` 출력
- [x] 채팅창에 `🤖 **AI Tutor**: ...` AI 답변 텍스트 출력 (음성 재생 전)
- [x] AI 답변 한국어 번역 출력
- [x] `[다시 듣기 🔁]` 버튼이 채팅창에 표시됨
- [x] AI 답변이 음성 채널로 재생됨

---

### TC-02. 다시 듣기 버튼 동작

**목적**: `[다시 듣기 🔁]` 버튼 클릭 시 마지막 TTS 오디오 재재생 확인

**시나리오**:

1. TC-01 흐름을 완료한다
2. 채팅창의 `[다시 듣기 🔁]` 버튼을 클릭한다

**기대 결과**:

- [x] 봇이 마지막 TTS 오디오를 다시 재생함
- [x] 재생 중 유저 발화가 차단됨 (isBotSpeaking 플래그)
- [x] 재생 완료 후 마이크 입력이 다시 활성화됨

**시나리오**:

1. 봇이 음성 채널에 있는 상태에서 `/leave` 실행

**기대 결과**:

## 8-2. 응답 시간 측정

### TC-04. STT 시작 타이밍 측정

**목적**: 발화 종료 후 1.5초 이내 STT + LLM 시작 목표 달성 확인

**측정 방법**:

1. 봇의 콘솔 로그에서 타임스탬프 확인
2. 무음 감지(`silence detected`) 로그 → STT API 호출 로그 사이의 시간 측정
3. STT 완료 로그 → LLM API 호출 로그 사이의 시간 측정

**기대 결과**:

- [x] 무음 감지 → STT 시작: **200ms 이내**
- [x] STT 완료 → LLM 시작: **100ms 이내**
- [x] 전체 파이프라인 (무음 감지 → 음성 출력 시작): **3초 이내**

## 8-3. 에러 시나리오 처리

### TC-09. 음성 연결 끊김 처리

**목적**: 음성 채널 연결이 갑자기 끊겼을 때 봇 상태 정상화 확인

**시나리오**:

1. 봇이 파이프라인 처리 중 Discord 연결을 강제로 끊는다
2. 봇을 다시 시작하거나 `/join`으로 재연결한다

**기대 결과**:

- [x] 봇 프로세스가 크래시되지 않음
- [x] 재연결 후 정상적으로 파이프라인 동작

---

### TC-11. 봇 발화 중 마이크 입력 차단

**목적**: 봇이 TTS 재생 중 유저 발화가 파이프라인을 시작시키지 않는지 확인

**시나리오**:

1. 봇이 TTS를 재생 중일 때 유저가 발화한다

**기대 결과**:

- [x] `isBotSpeaking = true` 상태에서 파이프라인 시작 차단
- [x] TTS 재생 완료 후 유저 발화 정상 처리

---

### TC-12. 입장 직후 오발화 방지

**목적**: `/join` 직후 잔여 오디오 패킷으로 인한 의도치 않은 파이프라인 시작 방지 확인

**시나리오**:

1. `/join` 명령어를 실행한다
2. 봇이 입장하는 즉시 아무 발화 없이 1~2초 기다린다

**기대 결과**:

- [x] 입장 후 1,000ms 쿨다운 동안 파이프라인 시작 없음
- [x] 쿨다운 이후 정상적으로 음성 감지
